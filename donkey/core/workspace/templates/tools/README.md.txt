# tools/ —— 工具开发约定

本目录存放本工作区可用的工具，由 `donkey init` 生成，可自由编辑 / 删除。

当前内置 3 个工具模块 + 1 个契约库：

| 模块 | 内容 |
| --- | --- |
| `filesystem.py` | 文件系统操作 7 个工具：读 / 写 / 复制 / 移动 / 删除 / 列目录 / 看属性 |
| `commandline.py` | 命令行执行 1 个工具：每次新建进程，不经命令解释器 |
| `webfetch.py` | HTTP 抓取 1 个工具：只读，带四道边界保护 |
| `changes.py` | **变更记录契约库** —— 含 0 个工具函数，只被 import |

## 一、装饰器与说明文字

- **装饰器从 `langchain_core.tools` 导入** —— 官方内置装饰器，不要自造工具协议：

  ```python
  from langchain_core.tools import tool
  ```

- **每个工具函数必须有 docstring** —— 它就是工具描述（description），模型据此判断何时调用。
- 工具名即函数名；参数用类型注解声明全部参数与返回值；**可选参数必须有默认值**。
- **命名**：工具文件名用小写下划线（如 `web_fetch`），函数名用动宾短语（如 `fetch_page`）。

## 二、路径白名单由你自管

donkey **不强制**任何路径白名单 —— 相对路径以**工作区根**为基准，绝对路径原样保留。
要不要把某些目录挡在外面，是你的工作区自己的事。

## 三、超时配置

每次外部调用都必须设定超时（建议 30 ~ 60 秒），超时后给出明确的错误信息而不是无限等待：

- 命令工具默认 **60 秒**；
- 网络工具默认 **30 秒**（上限 120 秒）。

## 四、错误处理建议

- 抛出**具体的**内置异常类型（`FileNotFoundError` / `IsADirectoryError` / `PermissionError` 等），不要把调用堆栈原样抛给用户；
- 或者返回**结构化**的结果 —— JSON 里带 ``error`` 字段与说明文字；
- 不要用宽泛的 `except Exception` 把错误吞掉。

## 五、工作区根是怎么推出来的

工作区根**恒为"存放 `tools/` 的那个目录"** —— 由契约库自身的位置推导：

```python
Path(__file__).resolve().parent.parent
```

- 本套工具**不读取任何环境变量** —— 工具的行为不得被环境变量改变；
- 移动 `tools/` 目录即改变相对路径的基准；
- 需要换基准就换目录布局，而不是加环境变量开关。

## 六、契约库与你的工具是一套的

`tools/changes.py` 是**变更记录契约库**，全工作区**只有这一套**变更记录格式：

- 它与你的自写工具**是一套的** —— 你的工具 `from .changes import ...` 即可复用；
- `donkey init --force` **不会覆盖**工作区里已存在的契约库（它是"用户已接管的文件"）；
- 但契约库与你的工具**必须版本匹配** —— 重置 / 升级前**请自行备份**；
- 契约库升级后，旧的变更记录仍按旧版本消费（消费方按 `version` 分派）。

## 七、网络工具需要你自己装 HTTP 客户端库

`webfetch.py` 依赖 HTTP 客户端库（如 `httpx`）。它是**渲染进工作区的模板依赖**：

- donkey 自身**不携带**、也**不保证**已安装；
- 缺库时导入即失败 —— 请在自己的工作区里安装：

  ```bash
  pip install httpx
  ```

## 八、改文件的工具怎么写（变更记录契约）

> **契约库是契约库，不是工具** —— `tools/changes.py` 含 **0 个** `@tool` 函数，只被 import。
> 请不要往它里面加工具函数。

任何会改文件的工具都 MUST 遵守下面六条：

1. **必须**用契约库的原子写函数落盘（`atomic_write_bytes(path, data)`），**不得**直接覆盖写
   （`Path.write_text` / `open(..., "w")`）—— 非原子覆盖会毁掉旧内容，未来的差异展示 / 回滚就无从谈起。
2. 写前用 `read_existing_bytes(path)` 取**旧字节**，写后用
   `build_change_record(action, path, old_bytes, new_bytes)` 生成变更记录，
   并**放进返回结果的 `change` 字段**。
3. 变更记录的模式由 `tools.changes.CHANGE_RECORD_VERSION`（当前 `1`）**冻结** —— **只增不改**：
   新字段可加，旧字段语义不动；消费方按 `version` 分派。
4. **必须**提供"声明期望指纹"的乐观锁（内置的写 / 复制 / 移动 / 删除四个工具**均已提供** ——
   你的工具 MUST 遵循同一形态）；**建议**同时提供"只算不写"的预览开关
   `dry_run`（内置的四个工具**均已提供**）。
5. 写完把 `change["applied"]` 置为真；预览模式保持为假。
6. **不要自己造指纹 / 差异逻辑** —— `tools/changes.py` 是全工作区唯一的变更记录产地；
   用户自写工具 import 它即可（`from .changes import ...`）。
