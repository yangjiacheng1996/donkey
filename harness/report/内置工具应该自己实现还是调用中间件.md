第 60 行"临时 shell session（workspace_root 留空）"是正确用法（避免 HITL + 持久 shell 的已知坑，参见 harness/LangChain_doc/middleware/built-in.md §Shell tool Note），但需要明确：到底是方案 A 还是 B。

# 回答
直接说结论：**三个内置中间件都不能满足你的需求，要么缺功能，要么违反你的硬约束（不允许 deepagents）**。下面是按你列的能力做的对照表。

## 二、三个不能用 / 不该用的硬伤

### 2.1 `FilesystemMiddleware` 是 deepagents 的东西

`harness/LangChain_doc/middleware/built-in.md:1271` 原文：

```python
from deepagents.middleware.filesystem import FilesystemMiddleware
# FilesystemMiddleware is included by default in create_deep_agent
```

`SubAgentMiddleware` 也是同样出处（`built-in.md:1332`）。你设计文档里 `agent.py 100% 基于 LangChain，不允许 import deep_agents 或 managed_deep_agents` 这一条**直接 ban 了这两个**。你的速查表把 `FilesystemMiddleware`、`SubagentMiddleware` 和 `ShellToolMiddleware` 放在同一行「编排 / 沙箱」分类里，没有区分 import 路径——这是个**埋雷**。

### 2.2 `FilesystemMiddleware` 默认 backend 不是磁盘

`built-in.md:1291-1321` 原文：

> By default, these tools write to a local "filesystem" in your graph state. To enable persistent storage across threads, configure a `CompositeBackend` that routes specific paths (like `/memories/`) to a `StoreBackend`.

也就是说：**默认情况下 `ls` / `read_file` / `write_file` / `edit_file` 操作的是 LangGraph 图 state，不是磁盘文件**——会话结束就没了。要磁盘必须用 `deepagents.backends.FilesystemBackend`，又回到 deepagents 依赖。

`LangChain复刻agent.py的可行性分析.md §牺牲2` 已经把这个坑标注了：你想要的是 profile tool 直接 IO 磁盘，`FilesystemMiddleware` 的虚拟 FS 反而是干扰项。

### 2.3 `ShellToolMiddleware` 与 HITL 冲突 + 超时能力不通用

两个硬限制，文档原文：

- `built-in.md:1129`：**"Persistent shell sessions do not currently work with interrupts (human-in-the-loop). We anticipate adding support for this in the future."** 你的设计文档恰好要求 HITL 必开，这条**和你 profile tool 用持久 shell 直接冲突**。
- `built-in.md:1234-1237` 的例子显示 `DockerExecutionPolicy(command_timeout=60.0)` 有超时参数，但 `HostExecutionPolicy` 没有任何 timeout / max_wait / max_output 参数（`built-in.md:1184-1192` 列了 `env`、`redaction_rules`、`startup_commands` 等，但没列 timeout）。`DockerExecutionPolicy` 要起容器、依赖宿主机 docker daemon，对内网 / 离线场景不友好。

## 三、建议：维持你 profile tool 自研的方案，但补一个 `search.py`

既然前两条都 ban 了，**profile tool 应该全部自研**。建议如下：

| 自研 profile tool | 用什么 | 备注 |
|---|---|---|
| `filesystem.py` | Python `pathlib` / `shutil` 自写 `@tool`，直接落磁盘 | 不走 `FilesystemMiddleware`（ban）+ 不走 `ShellToolMiddleware`（持久 shell 与 HITL 冲突） |
| `commandline.py` | `subprocess.run([...], timeout=N, shell=False)`，**每次新建进程**，不走持久 shell | 显式 `timeout` 掐断；不走持久 shell 就没 HITL 冲突 |
| `webfetch.py` | `httpx` / `requests` 自写 | LangChain 没官方 `webfetch` 中间件，必须自写 |
| `search.py`（建议补一个） | 直接调 `FilesystemFileSearchMiddleware` 注册的 `glob_search` / `grep_search` 工具名 | 这个中间件是纯 LangChain 且能力够用，可以**直接当 profile tool 引用**，不用自己实现 |

具体到你的设计文档：

- **删掉速查表里的 `FilesystemMiddleware` 和 `SubagentMiddleware`**——它们都是 `deepagents.*` 的，违反你的硬约束。
- **`ShellToolMiddleware` 在表格里加注脚**："因持久 shell 与 HITL 冲突，本项目**不**用；`commandline.py` 用 `subprocess` 自实现（每次新进程 + timeout）。"
- **`FilesystemFileSearchMiddleware` 从「沙箱」分类挪到「工具」**，作为 `search.py` 的实现来源（也可直接 import 它注册的 `glob_search` / `grep_search` 工具对象，加到 `tools=[...]` 里）。
- **永久记忆 / 永久块的磁盘 IO**：如果走 `memory/forever/`，也用 `pathlib` 自写 IO（建议干脆走 SqliteStore namespace，别自己造 JSON 文件）。

最终速查表里"沙箱"这一栏建议直接删掉，把 `ShellToolMiddleware` 的能力描述挪到 "提示"区——"本项目不用，用自研 `commandline.py` 替代"。

## 四、最终给你的建议（一句话版）

**坚持 profile tool 自研**。原因是：
1. `FilesystemMiddleware` 是 deepagents 的（违反硬约束）+ 默认 backend 不是磁盘；
2. `SubAgentMiddleware` 是 deepagents 的（违反硬约束）；
3. `ShellToolMiddleware` 持久 shell 与 HITL 冲突 + Host 模式无 timeout；
4. `FilesystemFileSearchMiddleware` 是唯一纯 LangChain 且能力完整的，但只覆盖 glob/grep，自研 IO 工具也得另外写。

你的 `filesystem.py` / `commandline.py` / `webfetch.py` 三件套方向完全正确，建议再补一个 `search.py`（直接复用 `FilesystemFileSearchMiddleware` 的工具对象）。
