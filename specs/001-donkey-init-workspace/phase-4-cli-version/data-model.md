# 数据模型：F001-P4 `cli_version` —— `donkey version` 查询版本号

**Phase**: F001-P4 / `cli_version` | **日期**: 2026-10-30 | **Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

> 本文件是 `/speckit.plan` 的 Phase 1 产物 —— 描述本 Phase 的**实体、取值状态机与计数口径**。
> 本 Phase **无持久化实体、无数据库 schema、无工作区写入** —— 数据模型只覆盖"版本号怎么来、怎么呈现"这一条链。


## 3. 取值状态机（底层取值的解析）

```text
                  ┌──────────────────────────────┐
   ① 入口          │  resolve_version()            │
   （CLI 调用）──▶ │  核心层 · 纯函数 · 无 IO 副作用  │
                  └───────────────┬──────────────┘
                                  │
                    ┌─────────────▼─────────────┐
                    │ ② importlib.metadata       │
                    │    .version("donkey")       │
                    └─────────────┬─────────────┘
                                  │
              ┌───────────────────┴───────────────────┐
              │ 返回成功（值 = 元数据版本）              │ 抛 PackageNotFoundError
              ▼                                       ▼
   ┌────────────────────────┐            ┌──────────────────────────┐
   │ ③ 以【元数据】为准       │            │ ④ 回退包内 __version__     │
   │    （不比较、不告警）    │            │    （donkey/__init__.py）   │
   └───────────┬────────────┘            └────────────┬─────────────┘
               └──────────────────┬──────────────────────┘
                                  ▼
                    ┌──────────────────────────────┐
                    │ ⑤ 底层取值（如 "0.1.0"）        │
                    └───────────────┬──────────────┘
                                    ▼
                    ┌──────────────────────────────┐
                    │ ⑥ version_string()            │
                    │    = "v" + 底层取值            │
                    └───────────────┬──────────────┘
                                    ▼
                    ┌──────────────────────────────┐
                    │ ⑦ stdout：展示值 + 行终止符      │
                    │    退出码 0                    │
                    └──────────────────────────────┘
```

| 状态 | 触发条件 | 行为 | 依据 |
|---|---|---|---|
| ② 命中 | 发行版 `donkey` 的分发元数据可读 | 取元数据版本 | FR-016 |
| ③ 不一致 | 元数据版本 ≠ 包内 `__version__` | **以元数据为准**（它代表用户实际安装的那一份）；MUST NOT 报错、MUST NOT 告警 | FR-018 |
| ④ 不可得 | 抛 `importlib.metadata.PackageNotFoundError`（包未安装 / 非标准安装 / 从源码检出直接运行） | 回退 `donkey.__version__`；MUST NOT 抛异常、MUST NOT 使命令失败、MUST NOT 输出空值 | FR-017 |
| ⑤ ~ ⑦ | 恒定 | 底层取值 → 加 `v` 前缀 → 单行输出 + 退出码 `0` | FR-013 / FR-007 / FR-028 |

### 3.1 B-4 · 陈旧安装形态下的双比对分支（e2e 必须显式断言）

> **B-4 是 §3 状态机的**判定分支**，不是新的取值来源** —— 取值来源仍**唯一**（FR-019：元数据 → 回退 `__version__`）；B-4 描述的是「元数据值 ≠ 工作树声明值」时**输出该等于谁**。

| 分支 | 触发条件 | 行为 | MUST NOT | 依据 |
|---|---|---|---|---|
| **B-4 元数据值 ≠ 工作树声明值（陈旧安装）** | `importlib.metadata.version("donkey")` ≠ `pyproject.toml` 的 `version` | **以分发元数据为准**（输出底层取值 = 元数据值）；该分支 MUST 由 e2e **显式断言** | MUST NOT 报错 / MUST NOT 告警 / MUST NOT 输出工作树声明值 / MUST NOT 被**静默接受** | FR-018 / FR-013 / SC-003（[research.md](../research.md) R-18） |

**B-4 与 B-3 的区别**：B-3 比较的是「元数据 vs 包内 `__version__`」（运行期内部一致性）；B-4 比较的是「元数据 vs 工作树声明值」（**验收期**的一致性判据）—— 二者不冲突：B-3 决定**运行期取谁**，B-4 决定**验收断言谁**。

**不变式**：
- **I-1**：任何路径下底层取值都**非空**且可被 `^v\d+\.\d+\.\d+$` 解析（展示值形态）；
- **I-2**：输出中版本值**恰好出现 1 次**（MUST NOT 出现第二个版本值）；
- **I-3**：同一条命令两次执行 → stdout **逐字节相同**（无时间戳 / 主机名 / 路径 / 进程号）；
- **I-4**：成功路径 stderr **为空**；
- **I-5**：命令**不触碰文件系统**（执行前后目录树的文件数 / 目录数 / 内容指纹全部不变）；
- **I-6**：底层取值与工作区清单的 `donkey_version` 字段**逐字节一致**（迁移比对口径，宪法 D-03）。

## 4. 关系（谁依赖谁）

```text
donkey/core/version.py
   ├── 依赖  donkey/__init__.py 的 __version__（公开导出；该文件零 import → 无循环依赖）
   └── 依赖  标准库 importlib.metadata（发行版 "donkey" 的元数据）

donkey/cli/cli_client.py
   ├── 依赖  donkey/core/version.py 的 version_string()
   └── 依赖  标准库 argparse（既有）

donkey/core/api.py
   └── 不依赖 version.py（本 Phase 只改 docstring；FR-020 末句：不新增 core.api 库 API）

tests/unit/test_cli_version.py
   ├── 依赖  donkey/core/version.py（单元层：直接测解析三分支）
   └── 依赖  donkey/cli/cli_client.py（单元层：断言 stdout 形态）

tests/e2e/phase/verify_phase_f001_p4.py
   └── 只依赖  子进程（donkey 控制台脚本 或 python -m donkey）+ 工作树文件（pyproject.toml）
        MUST NOT import donkey.* 业务代码（FR-033）
```

**依赖方向约束**：`core` → `donkey`（包根常量）→ 无反向依赖；`cli` → `core.version`；**无** `core` → `cli`（宪法 N-03）。

## 6. 术语表

| 术语 | 定义 | 不得与之混用 |
|---|---|---|
| **软件功能版本** | donkey 的**唯一**版本号 —— 图版本 ≡ 软件版本 ≡ 包 / 发布版本（FR-012） | 不叫"图版本"（那是同义的口语化说法）；不叫"包版本"（同义） |
| **底层取值** | 不带 `v` 前缀的版本号本体（如 `0.1.0`）—— 与 `pyproject.toml` / `__version__` / 清单 `donkey_version` 逐字节一致 | 不叫"版本值"（那是展示层的口径） |
| **一致性判据** | 底层取值与 `pyproject.toml` / `__version__` / 清单 `donkey_version` 的比对口径 —— **常规安装形态**下**逐字节一致**；**陈旧安装形态**下以**分发元数据**为准（FR-018），此时**不**逐字节一致（spec FR-013 / SC-003 已限定） | 不叫"版本一致性"（那是本条的口语简称） |
| **常规安装形态 / 陈旧安装形态** | **判定谓词**（本 Phase 全部形态词的唯一口径）：**常规安装形态** = 安装分发元数据值 == 工作树声明值（`importlib.metadata.version("donkey")` == `pyproject.toml` 的 `version`）；**陈旧安装形态** = 两者不等（输出 MUST == 分发元数据值，FR-018）；**陈旧清单形态**（陈旧安装形态的子集）= 工作树声明值 != 工作区清单 `donkey_version` 字段（清单值被 F001-P2 FR-021 锁死）→「输出 vs 清单字段」的比对 MUST **跳过** | 不叫"正常安装" / "标准安装"（与 spec 的「常规安装形态」**同义**，MUST NOT 当作两个条件）；详见 spec Key Entities「常规安装形态 / 陈旧安装形态（判定谓词）」 |
| **展示值** | `v` + 底层取值（如 `v0.1.0`）—— stdout 输出的那个字符串 | 不叫"版本号"（会与底层取值混淆）；**别名**：「版本值」= 本条的**同义词**（spec 全文沿用「版本值」指 stdout 那个字符串 —— 见 spec Key Entities「术语对齐（spec ↔ data-model §6）」，两者 MUST NOT 被当作两套概念） |
| **显示前缀** | `v` —— §4.5 的 `vx.y.z` 记法前缀；**不是**版本号的一部分 | 不叫"版本" |
| **元信息命令** | 只读地暴露工程元信息、不承载业务能力、不占用 exit code 段位、不需要 `donkey.core.api` 库 API 的一级命令（宪法 §4.2 修订后）—— 当前唯一成员 = `donkey version` | 不叫"辅助命令" / "调试命令" |
| **三套版本号体系** | 软件 / 包 / 发布版本 · 图版本 · workspace 格式版本（整数 `1`） | 前两套在本 Phase 已**合并为同一个数**；第三套**不暴露**（FR-021） |
| **段位 / 子段** | 退出码视角的单位（README §1.5）—— 本 Phase **不占用**任何子段 | 不叫"Phase"（开发视角） |
